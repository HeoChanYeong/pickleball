# 코트사이드 · 피클볼 운영 대시보드 — Pages v2

청팀과 백팀의 출석, 3개 코트 배정, 경기 결과를 운영진의 브라우저에서 관리하는 정적 웹사이트입니다. HTML, CSS, JavaScript, 로고와 메인 이미지는 모두 `docs/`에 있습니다. 별도 설치, 빌드, 서버 API, 계정 또는 API 키가 필요하지 않습니다.

기준 파일은 이전에 제공한 `courtside-github-pages.zip`입니다. 기준 ZIP의 SHA-256은 `b01f3e8f1889215e7c275986a8e974eca89a256343843447b065ea51e9d86be8`입니다. 그 이전본의 출처는 Sites 운영 버전 4, 커밋 `e7f4f2c79660cd774a59da91ec3a1c7172e736a9`입니다. 이번 변경은 GitHub Pages용 ZIP 사본에만 적용했습니다.

## 코트 예고와 음성 운영

1. **대시보드 → 음성 안내 켜짐**에서 켜기·끄기, 속도(0.7~1.5배), 기기에 설치된 한국어 음성을 선택합니다. 첫 클릭 후 자동 호출을 시작할 수 있습니다. 새로고침 직후에 호출 대기 명단이 있으면 **호출 시작**을 누르세요.
2. **다음 경기 예정**은 실시간 예상 명단입니다. 진행 중인 선수, 이미 호출 예약된 선수, 미출석·목표 달성 선수는 제외합니다. 같은 등급에서 청팀과 백팀을 두 명씩 고르고, 완료 경기 수가 같으면 먼저 출석한 선수를 예고합니다. 세 코트에 같은 사람을 두 번 예고하지 않습니다. 실제 배정은 기존의 출전 횟수·대기 순서 규칙을 따르므로 예고와 달라질 수 있습니다.
3. 실제 빈 코트가 생기면 네 명을 해당 코트의 **배정 전** 명단에 임시 예약합니다. 세 코트 모두 예약할 수 있고, 음성은 한 코트씩 안내합니다. 호출 도중에는 코트 번호, 양 팀 이름, 등급을 화면에서도 확인할 수 있습니다. 안내를 마치고 선수 자격을 다시 확인한 뒤에만 **경기 중**으로 바뀝니다.
4. **호출 중지**는 해당 코트를 화면 확인 대기로 바꿉니다. 다른 코트의 호출은 계속됩니다. **다시 듣기** 또는 **명단 확인 · 배정**으로 진행할 수 있습니다. 경기 중인 코트의 **다시 듣기**는 기존 대진을 읽어주며 기록과 출전 횟수는 바뀌지 않습니다.
5. 기기 내 한국어 음성이 없거나 재생이 거부·중단되거나 완료 신호가 오지 않으면, 코트에 표시된 네 이름을 확인하고 **명단 확인 · 배정**을 누릅니다. **음성 안내 끄기**로 바꾸면 유효한 예약도 즉시 정식 배정됩니다. 설치 음성 목록은 운영체제와 브라우저에 따라 다릅니다.
6. 출석 취소, 등급 변경, 목표 조정, 오늘 경기 초기화로 예약 자격이 사라지면 기존 호출을 무효화합니다. **경기 완료**에서 청팀 승리·백팀 승리·무승부 중 하나를 누르면 결과를 저장한 뒤 방금 끝난 코트의 다음 대진을 찾습니다. 다른 등급도 배정할 수 있으며, 다른 선수들이 모두 한 번씩 출전하기를 기다리지 않습니다.

상세 시험 내용과 공개 파일 검사 범위는 `SECURITY-REVIEW.md`에 있습니다.

## 먼저 로컬에서 열기

1. ZIP을 풀고 `README.md`가 있는 폴더에서 터미널을 엽니다.
2. Python 3가 설치되어 있다면 `python -m http.server 8000 --bind 127.0.0.1`을 실행합니다. 일부 환경에서는 `python3` 또는 `py -3`를 사용합니다.
3. 같은 컴퓨터의 브라우저로 `http://127.0.0.1:8000/docs/`를 엽니다. 로컬 시험에는 가상 선수 이름을 사용할 수 있습니다.
4. 종료하려면 터미널에서 Ctrl+C를 누릅니다. 실제 운영용 주소로 옮길 데이터가 있으면 먼저 **선수 명단 → 백업·복원 → 전체 기록 내보내기**를 선택합니다.

## 기존 Sites 명단과 경기 기록 가져오기

브라우저는 사이트 주소별로 저장소를 구분합니다. 기존 Sites에서 사용하던 데이터를 새 주소로 가져오는 작업은 한 번 필요합니다.

1. 실제 운영하던 기기와 일반 브라우저 프로필에서 기존 코트사이드 Sites를 열고 선수 수와 경기 기록을 확인합니다.
2. 기존 배포 버전 4에는 JSON 내보내기 메뉴가 없습니다. Chrome 또는 Edge에서 개발자 도구를 열고 **Application(애플리케이션) → Storage → Local Storage**에서 현재 코트사이드 데이터를 가진 사이트를 선택합니다. 사이트가 프레임 안에서 실행되면 해당 프레임의 저장소도 목록에 보일 수 있습니다. 키 이름은 정확히 `courtside.club.match.v1`입니다.
3. 그 항목 하나의 **Value(값)** 전체를 복사합니다. 텍스트 편집기의 빈 파일에 붙여 넣어 `courtside-legacy.json`이라는 UTF-8 일반 텍스트로 운영진 기기에 저장합니다. 값은 중괄호로 시작하는 JSON 객체입니다. 같은 프로필의 다른 항목은 복사할 필요가 없습니다. 키가 보이지 않으면 기존 경기를 진행한 주소와 프로필을 먼저 확인합니다. 저장된 값 없이 기본 명단만 보였다면 새 사이트에서 직접 등록할 수 있습니다.
4. 새 사이트의 **선수 명단 → 백업·복원**에서 파일을 선택합니다. 표시된 인원·경기 수를 확인하고 **전체 복원**을 누릅니다. 새 사이트의 현재 데이터가 교체되므로 그곳에 기존 기록이 있다면 먼저 전체 기록을 내보냅니다.
5. 선수 수, 출석, 코트 배정과 경기 기록이 일치하는지 확인합니다. 옛 버전의 승패 미기록 경기는 이력을 유지하며 승수 합계에서 제외합니다. 백업 JSON은 운영진이 개인적으로 보관합니다.

## 경기 당일 운영

- **선수 명단**에서 이름·팀·등급을 등록합니다. 같은 팀·등급의 여러 명은 쉼표나 줄바꿈으로 한 번에 등록할 수 있습니다. 같은 팀 내 동명이인은 구분 가능한 이름을 사용합니다. 이름으로 검색하거나 팀·등급으로 필터링할 수 있습니다.
- **대시보드 → 경기 설정**에서 1인 목표를 정한 뒤 **경기 시작**을 누릅니다. 대기실에서 실제로 도착한 사람의 이름만 누릅니다. 출전하지 않은 대기 선수는 출석을 취소할 수 있습니다.
- 출석한 같은 등급에서 청팀 2명과 백팀 2명이 가능하면 빈 코트에 배정합니다. 코트별 고정 등급은 없습니다. 완료 경기 수가 적은 선수가 우선이며, 동률이면 대기 순서를 사용합니다. 목표 미달 선수는 다시 출전할 수 있습니다. 팀별·등급별 출석 불균형이나 중도 목표 변경에 따라 일부 선수의 목표가 남을 수 있습니다.
- 경기 중 **선수 명단 → 등급**에서 변경한 등급은 다음 배정에 적용됩니다. 경기 중 목표를 바꿔도 진행 중인 대진은 끝까지 유지됩니다. 이름·팀 수정과 삭제는 현재 출석·출전 상태에 따라 제한됩니다.
- 코트의 **경기 완료**를 누르고 **청팀 승리**, **백팀 승리**, **무승부** 중 하나를 선택합니다. **경기 기록**에서 등급별·전체 팀 승수, 코트별 대진, 선수별 완료 횟수를 확인합니다.
- 다음 회차를 시작하려면 대시보드에서 **오늘 경기 초기화**를 선택하고 확인합니다. 선수 명단·팀·등급·목표는 유지합니다. 출석, 대기 순서, 진행 중인 코트, 오늘 경기 횟수를 비웁니다. 이미 완료한 경기는 **경기 기록 → 경기 회차**에 보관합니다. 진행 중인 경기의 결과를 남기려면 초기화 전에 승리를 먼저 기록하세요. 완료 경기가 없는 회차는 보관 목록에 추가되지 않습니다.

## 저장과 백업

| 메뉴 | 포함 항목 | 가져올 때의 동작 |
| --- | --- | --- |
| 선수 명단 내보내기 | 이름·팀·등급 | 현재 명단과 합칩니다. 같은 팀에 같은 이름이 있으면 기존 정보를 유지합니다. 등급 변경은 명단 화면에서 합니다. 운영 종료 상태에서는 오늘 경기를 초기화한 뒤 합칠 수 있습니다. |
| 전체 기록 내보내기 | 전체 명단·목표·출석·현재 대진·완료 경기·이전 회차 | 확인을 거친 후 해당 기기의 현재 자료 전체를 교체합니다. 기존 Sites 저장값도 이 방식으로 복원합니다. |

저장에 성공한 변경은 같은 주소와 일반 브라우저 프로필에서 창을 닫고 다시 열어도 유지됩니다. 기기·브라우저·프로필 사이의 자동 동기화는 없습니다. 사이트 데이터 삭제, 비공개 창 종료, 기기 분실 또는 브라우저 저장 공간 제한에 대비해 정기적으로 **전체 기록 내보내기**를 사용하세요. 브라우저가 저장 실패를 알리면 해당 변경은 저장되지 않았습니다. 저장 공간이 차면 먼저 전체 기록을 백업하세요.

GitHub Pages 저장소 경로마다 별도 저장 키를 사용합니다. 동일한 GitHub Pages 도메인의 다른 앱은 브라우저 보안상 같은 출처를 공유할 수 있으므로, 운영 명단을 다루는 도메인에는 신뢰하는 앱만 두세요. 경로나 도메인을 바꿀 때는 기존 주소에서 전체 백업을 내려받아 새 주소에서 복원합니다.

## 승인 후 GitHub Pages에 게시하기

1. 저장소 루트에 이 ZIP의 내용을 그대로 넣습니다. 루트에 `README.md`, `SECURITY-REVIEW.md`, `.gitignore`, `docs/`가 있고, `docs/index.html`과 `docs/.nojekyll`이 존재하는지 확인합니다.
2. 저장소 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**를 선택합니다. 게시 브랜치(예: `main`)와 **/docs**를 선택하고 저장합니다. 별도 GitHub Actions 워크플로는 필요하지 않습니다.
3. Pages에 표시된 주소를 열고 세 메뉴, 로고와 메인 이미지가 표시되는지 확인합니다. 최종 주소에서 운영진의 전체 백업을 가져옵니다.

`.gitignore`는 JSON 백업과 로그 등의 실수로 인한 추가를 줄이기 위한 설정입니다. 수동 업로드 시에는 이 ZIP에 들어 있는 파일만 선택하세요.
